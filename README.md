# Lookglass Worker

This Cloudflare Worker exposes the Lookglass API and runs the scheduled
monitor checks. The module entrypoint delegates HTTP requests to the Hono app
and delegates Cron events to the scheduler using the event's scheduled time.

## Bindings and variables

`wrangler.jsonc` defines the following bindings:

- `DB`: the D1 database named `lookglass-db`.
- `STATUS_BUCKET`: the R2 bucket named `lookglass-status`.
- `FRONTEND_ORIGIN` and `R2_PUBLIC_BASE_URL`: non-secret Worker variables.

`ADMIN_TOKEN` and `SESSION_SECRET` are Worker secrets. Use unique, high-entropy
production values; do not use the example values for a deployed Worker.

The checked-in `database_id` is intentionally the empty placeholder `""`.
Create the database first, then copy the generated `database_id` from the
`wrangler d1 create lookglass-db` output into `wrangler.jsonc`. The generated
ID must be copied before running Worker build or deploy validation. Never
invent or substitute a database ID.

For local development, copy `.dev.vars.example` to `.dev.vars` and replace the
clearly non-production token and secret placeholders with local random values.
`.dev.vars` is ignored by git.

## Setup and deployment

Run these commands from this directory:

```bash
npm install
npx wrangler login
npx wrangler d1 create lookglass-db
npx wrangler r2 bucket create lookglass-status
npx wrangler d1 migrations apply lookglass-db --local
npm run test
npm run typecheck
npm run build
npx wrangler secret put ADMIN_TOKEN
npx wrangler secret put SESSION_SECRET
npx wrangler deploy
```

Before local development, create the ignored variables file if needed:

```bash
cp .dev.vars.example .dev.vars
```

`npm run build` runs `wrangler deploy --dry-run`. Copy the ID generated by
Wrangler before using the build or deploy commands for validation. Depending
on the Wrangler version, dry-run validation may only display the D1 binding
with the empty placeholder instead of rejecting it; that does not make the
placeholder deployable. If validation rejects the blank ID, the scoped fix is
to copy the generated ID and rerun validation, never to guess a value. The two
`secret put` commands prompt for the values without placing them in this
repository.

## R2 public domain and CORS

Configure a custom public domain for the `lookglass-status` bucket in the R2
bucket settings, for example `https://status.example.com`, and set
`R2_PUBLIC_BASE_URL` to that same origin. The domain must be public so the
browser can read the generated snapshot.

Configure R2 CORS with the exact public Pages origin. A suitable rule for the
public snapshot is:

```json
[
  {
    "AllowedOrigins": ["https://lookglass-frontend.pages.dev"],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag", "Content-Length"],
    "MaxAgeSeconds": 3600
  }
]
```

Replace the example origin with the actual production Pages origin, and keep
it restricted to the origins that need public status access. The scheduled
Worker writes the snapshot at `public/status.json`. The public Pages app reads
that object directly from
`R2_PUBLIC_BASE_URL/public/status.json`; public dashboard traffic does not go
through a Worker API route or proxy.
